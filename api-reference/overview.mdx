The TruGen REST API is how you programmatically create agents, manage templates, ground them in your data, register tools, and read session records. Everything you can do in the [Developer Portal](https://app.trugen.ai), you can do here.

## Base URL

```
https://api.trugen.ai/v1
```

All responses are `application/json` unless otherwise noted.

## Authentication

Every request must include an `X-API-Key` header. Create keys in the [Developer Portal](https://app.trugen.ai/api-keys).

```bash
curl https://api.trugen.ai/v1/ext/agent \
  --header 'X-API-Key: YOUR_API_KEY'
```

<Warning>Your API key is server-only. Never embed it in browser or mobile client code. For client-side use, exchange the API key for a short-lived session token via the [JS SDK Authentication](/docs/sdks/javascript/authentication) or [Python SDK Authentication](/docs/sdks/python/authentication) flow.</Warning>

## Two-tier authentication model

TruGen uses two credentials, each with a different purpose:

| Credential | Where it lives | What it can do |
| --- | --- | --- |
| **API Key** | Your server (`X-API-Key` header) | Every REST endpoint. Create agents, manage templates, read conversations. |
| **Session Token** | Passed to the browser | Join one live conversation. |

See [JS SDK Authentication](/docs/sdks/javascript/authentication) or [Python SDK Authentication](/docs/sdks/python/authentication) for the full pattern.

## Resource model

The API is organized around a small set of resources:

| Resource | Purpose |
| --- | --- |
| **Agents** | The primary object — a configured conversational video agent with a prompt, avatar, voice, LLM, and tools |
| **Templates** | Reusable blueprints — share prompt, knowledge, and behavior across many agents |
| **Knowledge Bases** | Document collections your agents ground answers in via RAG |
| **Tools** | Callable actions your agents invoke during conversations (webhooks, MCP, integrations, client actions) |
| **MCPs** | Model Context Protocol server configurations |
| **Providers** | The set of LLM, STT, and TTS providers available in your environment |
| **Avatars** | Visual identities — stock or custom |
| **Conversations** | Session records — including full chat history, feedback, and usage |

## Common patterns

### Create an agent → embed it

1. `POST /v1/ext/agent` — create the agent, get an `agent_id`
2. Drop the [widget](/docs/integrations/widget-integration) or [iframe](/docs/integrations/embed-via-iFrame) with that ID
3. Users interact — sessions are automatically tracked

### Personalize per user

1. Create an agent once with the shared prompt
2. On each session, mint a session token with `userId`, `userName`, and `context`
3. The agent sees this context and personalizes accordingly

### Use a template across many agents

1. `POST /v1/ext/template` — create the template with the shared config
2. `POST /v1/ext/agentbytemplate` — spin up a new agent from the template

### Access session results

1. Handle the `call_ended` webhook — see [Event Callbacks](/docs/agents/callback)
2. Fetch the conversation record with [`GET /v1/ext/conversation/{id}`](/api-reference/endpoint/conversationgetbyid) — includes `chat_history`, `snippets`, `feedback`, `usage_json`

## Errors

Errors are returned as JSON with an `error` field:

```json
{
  "error": "Unauthorized: not a valid authorization api key"
}
```

## Pagination

List endpoints use `offset` + `perpage` query parameters:

```
GET /v1/ext/conversation?offset=0&perpage=20
```

The response includes an `X-Total-Count` header with the total match count for the query.

Additional filters vary per endpoint — check the individual endpoint page.

## Versioning

The API is versioned in the URL path (`/v1/…`, `/v2/…`). Breaking changes ship as new versions. Non-breaking additions ship in place; watch the [changelog](/docs/changelog) for notice.
